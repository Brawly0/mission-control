## How to work on it

- **Build and check:** `npm run typecheck && npm test && npm run build`.
- **Smoke tours:** `$env:MC_SMOKE="<dir>\s.png"; $env:MC_SMOKE_LOG="<dir>\s.log"; $env:MC_SMOKE_<TOUR>=...; .\node_modules\electron\dist\electron.exe .`
  - Free tours: `SHOTS=bot` (screenshots + real key presses), `HUB=<scratch>`, `BRIEF=<scratch>`, `NAMES=<folder>`, `SPEND=<scratch>`.
  - Tours that cost a few cents of Haiku: `TASKS`, `AUTOMATION`, `CHAIN`.
- **Release:**
  1. Bump `package.json`.
  2. Commit and push.
  3. Run `node scripts/release.mjs "<notes>"`. It creates a draft, builds, checks the 3 assets, then publishes.
  4. Run `git tag vX && git push origin vX`.
- **Docs:** each version updates `README.md` (features), `docs/ROADMAP.md`, an ADR in `docs/decisions/` (0001–0012), `docs/DEVELOPMENT.md` (smoke tours) and `docs/ARCHITECTURE.md` (files).

## Decisions to keep

- **Read-only Claude data:** never write to `~/.claude/`. The app's own data lives in `%APPDATA%\Mission Control\store.json`.
- **No email in the UI:** never show or send the user's email. Use the GitHub noreply address for commits.
- **Real data only:** every dashboard number is real; no placeholders.
- **Terminals keep their keys:** inside a terminal, plain Ctrl+letter keys go to Claude and the shell.
- **Briefings start from now:** they auto-save only from first run onward. Older ones are saved by hand from Knowledge.

## Gotchas

- **Editing files from the shell:** heredocs and `sed` in Git Bash often eat backslashes (regexes, `C:\` paths). Use the Edit tool for those lines, or write a `.cjs` script with the Write tool.
- **PowerShell:** `Set-Content` adds a BOM, which breaks `package.json`.
- **The installed app shares `%APPDATA%\Mission Control`:**
  - Smoke tests use `index-smoke.db` so they don't corrupt the real index.
  - A dev run while the installed app is open still shares `store.json`.
- **Smoke screenshots:** they need `win.focus()` and `setBackgroundThrottling(false)`, or frames lag and key presses don't arrive.
- **`--mcp-config` takes several values:** always use the `--mcp-config=<file>` form.
- **Week math:** use calendar days (`setDate`), not 24-hour steps. Daylight saving changed this weekend.
